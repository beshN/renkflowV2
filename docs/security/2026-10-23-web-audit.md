# Web security audit — 23 October 2026

Base: main `1df8443b`. This review retains Auth.js, private storage, the existing tenant guards and production command engine. Tests use disposable local PostgreSQL and synthetic identities. No attack traffic or schema changes were sent to production.

## Changes

| Area | Corrected boundary |
| --- | --- |
| Login tickets | E-mail verification tokens no longer authenticate an SSO login. Dedicated tickets store SHA-256 hashes, expire in five minutes, and bind to the exact host, company and initiating browser. Atomic redemption permits one login. Membership removal and the global session cutoff invalidate pending tickets. |
| OAuth and MFA | Google identities with account MFA enter the existing OTP/recovery-code path before a member session is created. Unverified Google e-mails cannot link an account. Temporary tickets travel in a URL fragment and are promptly removed from the address bar. |
| Company OAuth | The Auth.js core receives the actual validated company origin instead of the fixed AUTH_URL. Auth.js encrypted state and PKCE relay through the existing central registered Google callback. Cookies remain host-only. Unknown hosts fail closed. |
| Enterprise SSO | Browser-bound flow state precedes provider work; the callback reads SAML form data once. State consumption is atomic, and provider/company/expiry checks remain attached to the consumed state. Disabled providers cannot finish a callback. |
| SSO provisioning | Domain restrictions also apply to OIDC; explicitly unverified e-mails are rejected. A tenant-controlled IdP cannot automatically claim an existing global or cross-company account. Unmapped group names cannot promote newly provisioned members to owner/admin. |
| AI office | Staff read their own tasks and files within the read scope captured at creation. Unrestricted managers can supervise the firm. Narrowed roles cannot read historical unrestricted outputs, including their own; task text, actions and private file bytes share this rule. Removed/demoted creators cannot continue sending data to models or saving/reviewing deliveries. |
| Browser writes | The shared Origin check compares protocol as well as host and rejects malformed origins. JSON media types are matched exactly. Header spoofing does not select another origin. |
| Dependencies | Web Next.js and its ESLint config now require 16.4.2; the web lockfile uses the patched release. The existing sharp version already satisfies the image advisory's workaround, so a version flag is not presented as proof of an exploitable RCE. |
| CI execution | The repository's platform policy was changed from `first_time_contributors` to `all_external_contributors` and read back successfully. Every external fork run now needs approval. Web validation also skips foreign heads, explicitly requests read-only contents permission and does not persist checkout credentials. A PR-controlled YAML condition alone is not a trust boundary. |

## Evidence

- `npm run validate`: tenant/backend/environment guards, typecheck, lint, 200 Jest suites / 1,427 tests, production build and packaged PDF worker/extraction verification passed. Three existing unused ESLint suppression warnings remain.
- `test-auth-security.ts`: real PostgreSQL ticket purpose separation, expiry, browser/host/company binding, global cutoff, revoked membership, twelve concurrent redemptions yielding one winner, MFA challenge without spending the ticket, SSO provisioning restrictions, and actual Auth.js PKCE/state/callback/cookie behavior.
- `test-oauth-mfa-runtime.ts`: a real Next.js server handles a locally signed simulated Google identity; the real HTTP response carries the private browser proof, no member session exists before OTP, one session is created after a recovery code and ticket replay is refused. This does not claim a live Google account sign-in was exercised.
- `test-office-workflow.ts`: actual private file bytes, colleague access denial, denied approval, creator demotion, normal manager approval and existing model review workflow. External model transport is simulated.
- Unit regressions cover the SSO POST callback, OAuth MFA policy, OTP interaction/retry, role scope changes, mid-run access loss, same-origin attacks, and the existing station and tenant invariants.
- The broad local integration run passed 56/58 scripts. Its assistant UI test collided with a concurrent build; its stress test ran before the existing postinstall driver patch was restored after dependency maintenance. Stress passed its independent rerun. The PR gate must rerun the complete suite sequentially after build; these initial failures are not called passing tests.
- Web production dependency audit (`npm --prefix apps/web audit --workspaces=false --omit=dev`) reports zero known advisories. The development tree still reports nine upstream build/lint dependency findings (seven high, two moderate); automatically switching Tailwind major versions or downgrading Next.js is not an acceptable fix. This is not a clean audit claim for every mobile/root workspace.
- A pattern scan of tracked text files found no provider key, GitHub token, AWS key or private key. Its database credential candidate is the local Playwright fixture. Pattern scanning is not a full historical secret audit.

## Release and compatibility

1. Migrations `078_sso_login_tickets.sql` and `079_office_read_scope.sql` are additive and registered in the existing deploy ledger. Exercise them on an isolated branch and take a fresh production backup before release, following `docs/runbooks/backup-restore.md`.
2. Old e-mail/SSO tokens cannot be used as login tickets. Start a new SSO flow. Newly provisioned SSO members receive the member role; elevated access is assigned explicitly by the administrator.
3. Existing cross-company/global accounts use their verified password or Google sign-in instead of implicit enterprise IdP account linking. Explicit federated account linking/domain-ownership verification remains a separate feature.
4. Historical AI office tasks have no trustworthy read-scope snapshot. Unrestricted managers retain access; restricted staff cannot read those unredactable outputs. New tasks capture a read scope.
5. CI and the Vercel preview must validate the exact PR head. Production migration/release and real wildcard DNS/TLS are separate steps and are not claimed by this report.
6. The existing self-hosted runner is a personal Mac. Do not approve untrusted fork code onto it; review and import changes onto a trusted branch first. Fully isolated ephemeral runners remain the stronger boundary for external contributions. Existing default workflow permissions were already read-only and were preserved.
